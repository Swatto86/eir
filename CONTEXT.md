## Decisions

2026-09-27 | Eir | Machine-wide winget upgrades run as the service; per-user ones as the user | Running every winget call under the desktop user's filtered token, so per-user packages stay visible, made machine-wide installers raise UAC prompts (Chrome, PowerShell 7, the Visual Studio installer). Each upgrade now first asks, as the user, whether the package is installed machine-wide: if so the LocalSystem service upgrades it with `--scope machine`, otherwise the user's token is used (also the fallback when the service's winget cannot start or see the package). The user's elevated (linked) token was rejected because its installers would run as administrator from the user-writable Temp folder, a silent elevation route for anything running as the user.

2026-09-26 | Eir | PowerShell scripts can never be always-approved | Always Approve is keyed by `FixAction::dedup_key` and every `powershell_diagnostic` script shares one key, because the AI writes each script afresh, so one approval of a read-only script had let every later AI-written script run as SYSTEM unreviewed, the very action `policy.toml` keeps off the auto-run list. The service now refuses and never honours Always Approve for scripts (`FixAction::can_always_approve`), the tray does not offer it on script cards and a grant saved by an earlier build is removed at start-up, while Ignore still works. This removes authority rather than adding it.

2026-09-26 | Eir | The updater leaves unverifiable and per-user apps alone and pauses repeat failures | An app with no registered version cannot be verified after an update (one failed every day), and an app registered only in a user's hive would get a second copy installed for SYSTEM if its installer ran as SYSTEM (many keep themselves current anyway), so both are skipped and named in the run notes. An app that fails two runs in a row is paused for 2 days, then 4, then a week (`updater/backoff.rs`), because the same failures cost an AI web search every day; Retry on its row still runs at once. No authority was added: the native path's host, hash and Authenticode gates are unchanged.

2026-09-25 | Eir | Headless Linux build of eir-svc, controlled by the `eirctl` CLI | `eir-svc` also builds and runs on Linux under systemd with no tray, and `eirctl` speaks the same `UiRequest`/`ServiceMsg` JSON-line protocol over a Unix socket (peer credentials checked at accept), so the decision loop, policy gate and approvals are shared and only the OS-facing edges are `cfg` splits (ARCHITECTURE.md, "Linux platform split"). It is deliberately narrower than Windows because it targets a shared, security-tool-dense, multi-service host where an unattended restart by a second autonomous agent is a higher coordination risk than on a single-user PC: only the `FixAction`s with a real Linux mechanism exist (service start/stop/restart, log and disk clean-up, process kill, file delete), the auto-execute whitelist is empty (every fix, including clean-ups that could remove evidence other security tools rely on, needs a human `eirctl approve`), and a two-layer protected-units backstop (a compiled list plus an empty-by-default host drop-in) guards `systemctl stop`/`restart` independently of `policy.toml`. When `eir-svc` runs as root the AI CLI is dropped to `[api] linux_ai_user` with only its primary group and no-new-privileges (`running_as_local_system()` had been hard-coded false off Windows, which would have run it as root), and the optional `[notify]` alert hook ships disabled with no call site and is never configured on a host without Swatto's go-ahead.

2026-09-24 | Eir | The WebDriver end-to-end suite drives the real binaries in portable-mode isolation | `e2e/` (WebdriverIO + tauri-driver) drives the real debug `eir.exe` and `eir-svc.exe` with no app-side test plugin, running the service in portable mode on a random pipe with `LOCALAPPDATA` redirected per run so the installed service and its state are never touched, and stopping only the PIDs the suite started. The AI is a fake `claude_cli` that always returns no problems, so the real executor can never act on the test machine; drivers are pinned and hash- or signature-checked in CI and located, never downloaded, locally.

2026-09-22 | Eir | OpenCode runs get a scratch `opencode.json` that disables the user's MCP servers | OpenCode merges the user's global config into every run, so an unattended cycle inherited their interactive MCP servers (Playwright browser, computer use) and opened a visible automated browser to research log entries. Each scratch workspace now carries a project-level config disabling every MCP server named in the global one (hook: `UserCliSpec::workspace_files`); built-in web tools stay available for update checks.

2026-09-06 | Eir | No bundled fixed WebView2 | The installer and the portable build use the machine's Evergreen WebView2 runtime (`webviewInstallMode: downloadBootstrapper`) instead of bundling a fixed runtime, which shrank the NSIS installer from about 220 MB to about 8 MB; upgrades delete any leftover `Microsoft.WebView2.FixedVersionRuntime.*` tree in Program Files.

2026-08-04 | Eir | Codex image attachments use the attached `--image=<file>` form | Ask screenshots reach the Codex CLI as files written into the per-call scratch workspace under generated names (`eir-image-N.ext`, never derived from the attachment name) and passed as `--image=<name>`. The attached form is deliberate: `--image` is multi-value, so a space-separated form directly before the trailing `-` stdin sentinel could swallow the sentinel as a second filename.

2026-07-26 | Eir | Subscription CLIs run as the active desktop user, never as SYSTEM | The service is LocalSystem but the AI CLIs are the user's own installs and logins, so each provider CLI is resolved and launched under the sole active desktop user's token, and scratch-file I/O inside the user's profile is impersonated so SYSTEM never follows a user-controlled reparse point; the Linux equivalent is the privilege drop to `[api] linux_ai_user`.

2026-07-04 | Eir | User-initiated actions carry only opaque ids | Disk clean-up and startup toggles from the tray send only opaque ids; the service rebuilds the action from its own last-scan state and routes it through the same policy gate (`route_user_action`), so repair authority stays in the service. Logon scheduled-task toggles are forced through approval (`force_approval`) even though `task_disable` is AI-whitelisted, matching `startup_set`'s human-confirms rationale; Ask Eir is diagnostic-only, so nothing parsed from an answer is ever executed.

2026-06-26 | Eir | Keep UI and service as separate processes joined only by newline-delimited JSON over `\\.\pipe\EirSvc` | This keeps LocalSystem repair authority in the service while the medium-integrity tray app remains a thin renderer/command surface.

2026-06-26 | Eir | Self-improvement is conservative-only learned facts | Audit-derived learning may skip, deprioritise, suppress noise, or reduce confidence, but it cannot enable actions or raise confidence; this keeps local adaptation from expanding authority.

2026-06-26 | Eir | Advisor mode is bounded escalation, not model-controlled policy | The AI may ask for deeper analysis or trigger low-confidence escalation, but Rust chooses the configured tier and enforces a daily escalation count cap of 24 (`MAX_ESCALATIONS_PER_DAY`). The advisor's daily USD budget and the updater's per-run USD budget were removed on 2026-07-24, so that count cap (with the per-run app and attempt caps) is the only backstop; spend stays visible in the usage card.
